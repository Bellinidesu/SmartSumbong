## 1. Workspace widgets (#131–#136)

**Backend (#131, migration 0132).** All 120 approved widgets got their data and
writes.

- Migration **0132_workspace_widgets**: 16 tables (each person's widget choices,
  the barangay's Workspace settings, team posts with read receipts, polls,
  staff birthdays, leave, credentials, the duty roster, patrol checkpoints and
  scans, a private shift check-in, relief tallies, safe-point notes, minigame
  scores) with row-level security, and the functions behind them.
  10 rolled-back checks in `supabase/tests/14_workspace_widgets.sql`.
- `admin/widgets.php` (reads, administrators only, JSON) and
  `admin/workspace-act.php` (writes, CSRF token). A failed data group never
  takes another down; an outside source that fails serves its last good copy.
- `admin/includes/feeds.php`: outside feeds (weather, air, sea, quakes,
  holidays, RSS) read on the server, cached, and guarded against redirects to
  private addresses.
- `admin/includes/hazards.php`: PAGASA warnings and cyclone track, GDACS alerts.
- `admin/includes/osm_layers.php`, `tools/build_safe.php`,
  `admin/assets/data/safe-b183.json`: evacuation centres and safe points.
- `docs/WIDGETS.md`: the contract.

**The screen (#132).** The slim widget rail on the Workspace, the library
picker, the alarm, the weather tile on the briefing bar with the engine's
glow; the engine `widgets-core.js` and eight modules loaded on demand
(`widgets-{live,cases,team,tools,apps,rss,games,me}.js`); 12 widgets on by
default. Script budget raised to 16 KB per file on purpose.

**Polish after a close look at all 120 (#133).**
- Weather, air, tide and quake widgets ask the same public API from the
  browser when the server's request is refused (the content-security policy
  allows exactly those hosts).
- PAGASA and GDACS read in parallel; GDACS capped at 4 seconds with its last
  good copy standing in.
- Fixed: class-name collisions that drew stray pills, chart heights, the mini
  map, the 8-ball showing code, news order, holiday names by language.

**Preview (#134–#136).** A page of every widget live (#134) was replaced by a
round **eye button** on every widget in the library that opens a live preview
without adding it (`admin/widget-view.php?w=id`, which saves nothing).

## 7. Secrets

- **The vault.** Every project secret that cannot be recreated (both `.env`
  files, the release keystore and `key.properties`, the Firebase
  service-account keys, the Figma token, earlier `.env` backups, and a
  database export holding residents' personal data) is now in one file
  encrypted with **age**, in `vault/` (its own private repository; the public
  repository ignores the folder, #142). Its key is locked with **Windows
  DPAPI** to the maintainer's account on the maintainer's PC: there is no
  passphrase and no other copy, by choice. Anyone with the repository, a copy
  of the disk, or a hosting login can open nothing.
- **Originals removed** after the vault restored all 37 files byte for byte:
  the loose Firebase keys and Figma token, the old database export, and spare
  keystore and `.env` copies. The working copies the build needs stay.
- **A full-text scan** of the workstation for every secret value found them
  only in the two working `.env` files. One apparent match was placeholder text.
- **Release key fingerprints** recorded for restricting the Firebase API keys
  (SHA-1 for Google Cloud's Android restriction, SHA-256 for Firebase).
